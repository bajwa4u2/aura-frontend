### Two Apple-specific corrections to this block

Written first as a copy of the Play line and then checked against the iOS
source, because Apple's platform is not Android's:

- **"Aura calls join the phone's own call history" was wrong for iOS.** On
  Android that whole integration is new in 1.4.2 (`35ce2864`), so the Play line
  stands. On iOS, CallKit has reported *incoming* calls since 1.4.0
  (`f13fb82e`); what 1.4.2 adds is the *outgoing* half (`5ffed711` — before it,
  `CXStartCallAction` appeared nowhere in the project, so iOS held no record of
  a call Aura placed). Restating a 1.4.0 feature as new would have been a false
  claim to Apple reviewers and to customers, so the line now names the half
  that actually changed.

- **"A steadier desktop layout" means nothing on an iPhone and iPad listing.**
  The shell work (`a5828953`, `d2c74c63`, `5ff580f9`, `f24d3a1e`) is
  width-driven rather than desktop-only, so it reads "wide screens" here. It is
  not claimed as an iPad-specific change, because no iPad-specific change was
  verified.

## Deliberately NOT said

- **Nothing about what was not certified.** The 1.4.2 record names three open
  items — iOS was not archived because the build host is Windows, the Android
  device exercise is blocked because no handset is attached, and the Store MSIX
  cannot be sideloaded because a Partner Center publisher identity has to be
  Store-signed. All three are **environment and platform facts**. Written into
  store copy they would read as product limitations, which would be inaccurate.

- **Nothing about the AI provenance correction.** Before this release the same
  post disclosed `LIKELY_AI` with content credentials on the public feed and
  disclosed nothing at all to a signed-in member or inside an institution. It
  is fixed at the projection boundary and was measured against production
  before and after. Whether a store listing should announce a corrected trust
  defect is a founder decision, not an engineering one, so it is drafted
  nowhere above and raised instead.

- **Nothing about session storage.** `22dddae6` moved the session out of a
  readable file into per-platform secure storage. It is real and it is a
  security improvement, but a release note that draws attention to where
  credentials used to live invites the question of what that meant for earlier
  versions. Available if the founder wants it; not assumed.

- **No counts, metrics or customer numbers** appear anywhere.

### What changed and why

| | Was | Now |
|---|---|---|
| Short description | "Write, publish, and engage in thoughtful public discourse on Au…" | public-first civic discourse, people and institutions speaking accountably |
| Full description | "a platform built for **thoughtful writing**, responsible discourse, and institutional dialogue" | the canon's Identity sentence, then what a person can actually do |

**Every claim is checkable.** No advertising and no cross-app tracking are true
of the binary — no ad SDK, no IDFA, no analytics SDK. AI-assisted composition
with human approval is the canon's own wording. "See when a message was sent
and read" depends on **1.4.2 being the build on the track**; it is not true of
1.4.1.
