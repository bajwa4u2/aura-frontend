# Global Navigation / Return-Path Authority — implementation

Founder authorization 2026-08-25, following the audit in
`2026-08-25-return-path-authority-audit.md`. Evidence for the after-state is
`return_path_recensus.csv` / `.json`, regenerated by
`test/navigation/return_path_recensus_test.dart`.

---

## 1. The architecture, as built

```
ReturnPathAuthority.resolve(
  path, canPop, isAuthed, exists, hasUnsavedWork?, institutionContext?
) -> ReturnAction { semantic, destination?, label? }
```

Nine semantics, all reached by the census: `stackReturn`, `parentReturn`,
`contextReturn`, `flowCancel`, `flowComplete`, `modalDismiss`,
`deepLinkFallback`, `rootNoReturn`, `terminalExit`.

**The two entry modes are asked, never guessed.** `canPop` IS the distinction
the ruling's §8 draws: a real Aura journey is unwound (mode A); a direct entry
derives a contextual parent (mode B). Nothing manufactures history.

**Derivation order for mode B**, all evidence-driven rather than tabulated:

1. flow surface → `flowCancel` (Cancel is not Back)
2. institution section root → `contextReturn` to the institution
3. longest registered path-prefix → `parentReturn`
4. contextual fallback → `deepLinkFallback` (institution → messages → admin →
   me → institutions → discover → the viewer's own home)

Step 3 asks the route tree rather than a hand-written parent map, because a
second list is a list that drifts.

### Relationship to `destination_continuity.dart` (RC4)

**A sibling, not an extension** — as ruled. RC4's subject is *a gate refusing a
destination*; this one's is *a person legitimately somewhere, wanting out*.

They touch in exactly one direction: `safeDestination` holds a return
destination to RC4's shape rules (no scheme, no authority, no smuggled origin,
no control characters).

**One deliberate disagreement, and it is the point of being siblings.** RC4
refuses `/` outright, correctly: as a preserved gate target, "come back to the
root afterwards" says nothing a gate could not do by default. But `/` is a
registered destination and the right way out of an informational page for
someone signed out. Found by the render test — the control appeared on
`/terms`, was tapped, and nothing moved. Conflating the two authorities would
have meant weakening RC4's open-redirect refusal for every gate in the product
to fix one return.

`RouteRegistry` is built from the live `GoRouter` configuration and matches
patterns, so `/institution/x/spaces` resolves through
`/institution/:institutionId/spaces`.

## 2. Presentation

| layer | responsibility |
|---|---|
| `ReturnPathAuthority` | what returning MEANS |
| `ReturnPathFrame` (in `AppShell`) | presents it, once, for every routed surface |
| `AuraScaffold` | title / leading / actions / home — **not** return semantics |
| screen | content, and only genuinely screen-specific behaviour |

`ReturnPathFrame` sits in `AppShell` because 139 destinations needed an
affordance and only 96 compose `AuraScaffold`; a page-level home would have
reached most of the product and quietly missed a third of it.

It renders **Back** (with the destination named, when known) for hierarchical
semantics and **Cancel** for flow semantics. The ruling is explicit that these
must not be flattened into one arrow, and they are not.

**`AuraScaffold` grew the header it always accepted** (§1). It had taken
`title`, `leading`, `actions`, `centerTitle` and `showHomeAction` and rendered
none of them; 18 screens passed `leading:` believing they were providing a way
back. `AuraPublicationLayout` opts out — it presents its own title in its hero,
so the shared header would have shown it twice.

All 153 literal `context.go` sites were classified by semantic intent. **55
migrated.** The ruling refuses a mechanical global replacement, and 98 sites
were deliberately left as replacement navigation:

### The defect only a handset could find

Android system back returned to the real predecessor while the visible control
sent the person to the public root. Two mechanisms disagreeing means one of
them is lying about where the person is — and no browser or desktop harness can
test this, because neither has a system back gesture.

Root cause, measured in two steps:

1. **A shell-internal push does not rebuild the shell.** Pushing a destination
   inside the SAME shell adds a page to the shell's navigator without
   re-invoking its builder, so the frame kept the previous destination's
   answer — the control read "Back to Aura" for `/mission` while the person
   stood on `/terms`.
2. **`canPop` lags the location by one frame.** Listening to the route
   information provider fixed the location, and a probe still printed
   `FRAMEBUILD loc=/terms canPop=false` against a router that answered `true`
   two pumps later.

The frame now rebuilds on the notification **and** again after the frame, and
the **action is re-resolved at tap time** rather than taken from what was drawn.
The label may lag a frame; the action may not, because that is the difference
between unwinding one step and being sent to the root.

### Regression protection (§4, §17)

`return_path_regression_test.dart` drives the real router:

* ten consecutive `refresh()` calls build no history — **REFRESH IS NOT
  NAVIGATION holds**;
* a canonical redirect leaves nothing to return to;
* `push` then `pop` returns to the actual predecessor;
* roots acquire no Back even mid-journey; Cancel is never hierarchical;
* institution context survives; Meetings/Live and the auth gates are not framed;
* the protected guard is narrow — ordinary destinations are NOT protected.

Building these found that discarding the routed child leaves the delegate with
zero route matches, so `canPop` answers false for everything and such a test
passes while proving nothing. They render the real child.

### Institution continuity (§11)

13 chains certified: spaces, a Space, members, units, a unit, announcements, an
announcement, a post, join requests, invites, domains, public engagement,
availability. Every one returns **inside** its institution, and every
destination is one the app renders.

## 6. Modal / flow (§6, §7)

The 15 full-height sheets **stay sheets**, classified individually by behaviour
rather than dimensions: every one is "act on the thing I am looking at". None
needs deep linking, refresh restoration, shareability or durable task
continuation.

Nothing traps: no sheet opts out of dismissal; exactly one dialog is
undismissable and it is the acknowledgement *after* an account has already been
deleted, which still carries an explicit action. The surfaces pushed outside
go_router keep their exits.

## 8. Protected boundary (§13)

**Zero Meetings/Live/realtime source files modified** across the entire chapter,
verified against the audit commit. Their 160 tests pass. `ReturnPathFrame`
declines to frame them by design — which is also what lets them adopt this
later without a fork: the authority already *describes* them.

**The 19 Meetings/Live surfaces without an affordance are preserved as a
finding**, returned for separate authorization.

## 9. Incidental

A pre-existing layout overflow in the public home hero pill (76px at 800 wide,
1px at 1600) blocked every test that renders a real destination. Fixed with a
`Flexible`, and recorded here because it was not part of the authorized scope.

Two further pre-existing conditions were worked around rather than fixed, and
are reported rather than left silent:

* the **institution rail** overflows by 15px at the default test window
  (`rail_modules.dart:1791`). The signed-in journey runs at a workspace-sized
  surface instead. Not a navigation defect; not in scope.
* the Windows harness disposed its provider container while its own dio work
  was in flight, throwing late and against whichever test ran next. Latent
  until a neighbouring test began driving real navigation; fixed.
