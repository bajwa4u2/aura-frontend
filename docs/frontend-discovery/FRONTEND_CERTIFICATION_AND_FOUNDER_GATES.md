# Frontend Reconstruction — Certification Layers & Founder Gates

---

## 1. Certification layers — never flattened

| Layer | Meaning | Where it can be earned |
|---|---|---|
| **Architecture** | the authority is correctly shaped | locally, per chapter |
| **Implementation** | it is built, migrated and gated | locally, per chapter |
| **Product-Behavior** | it behaves correctly as a product | per chapter, at its founder checkpoint |
| **Cross-System** | client and backend agree | C1 · C5 · C8 · C10 |
| **Real-Boundary** | verified on real devices/platforms | **C9** substantially; **C10** for media scale |
| **Founder Product Acceptance** | founder accepts the product | per checkpoint, consolidated at **C11** |
| **Item 17 / Release Gate** | integrated release certification | **C11 only** |

> **A lower layer passing never implies a higher one.** No chapter may claim Real-Boundary or Item 17 locally.

## 5. Representation alignment — synchronisation points

**Process (never varied):**

```
DISCOVER CONFLICT → BRING TO FOUNDER IF SEMANTIC → RESOLVE CANONICAL LANGUAGE
  → UPDATE RELEASE CLIENT + REPRESENTATION → ENFORCE
```

| Chapter | Representation touchpoint |
|---|---|
| C0 | canonical nouns, CTA families, state and temporal verbs |
| C1 | acting-identity language |
| C2 | identity, presence, **verification** language |
| C3 | destination and section names |
| C4 | attention/obligation language |
| C5 | Post/Works, Send/Publish, designation and approval language |
| C6 | participant/speaker/host and transfer language |
| C7 | **Correspondence vs Conversation vs Message** |
| C8 | Room vs Meeting vs Live; Member vs Participant |
| C9 | platform-specific language |
| C10 | Live/public participation language |

> **Representation reconciliation may run in parallel with implementation only after the semantic wording is founder-frozen.** It must never race ahead of unresolved product language, and implementation agents must never silently choose between repositories.
